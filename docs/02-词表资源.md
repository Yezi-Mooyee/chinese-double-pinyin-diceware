## 实测格式

### `raw-cryptogun-wordlist.txt`

```
0 0000 0000 0000	   0	women   	例: 我们 他们 它们 她们
0 0000 0000 0001	   1	tamen   	例: 他们 它们 她们
```

格式为 `位 <TAB> 二进制 <TAB> 十进制 <TAB> 拼音 <TAB> 例: 若干汉字`。

- 8192 行，全部 5 列
- **最后一列是一串同音词示例**，并不是该拼音对应的某一个词（`women` 给的是「我们 他们 它们 她们」四个词）
- 所以这份词表不能直接当「每行一个中文词」使用，它本质是「拼音 → 同音词群」的索引
- 本项目要的是「词 → 读音」的确定映射，因此转换脚本取每条拼音下的**第一个**例词
- 拼音列全部由 `a-z` 组成，无异常字符

### 为什么没用 cfbao 版

| 指标 | cfbao 版 | **cryptogun 版** |
|---|---|---|
| 26 个常用探针词命中 | **0 / 26** | **22 / 26** |
| 词性构成 | 8121 双字 + 14 单字 + 57 三字 | **8192 全双字** |

cfbao 的拼音要构成**前缀码**以保证拼接无歧义，代价是砍掉大量常用词：「中」在表中 ⇒ 所有 `zhong…`（中国、中文、中心）全被排除。

本项目用双拼**定长码**，本来就自带唯一可解码性质，不需要前缀码，这个约束对我们是纯损失。

另外 cryptogun 版不含单字词，而单字不是现代汉语里的独立记忆单位。

（cfbao 链路是 GPL-3.0，其脚本与产物均未随本仓库发布。这里保留对比数据，是因为它是「为什么换词表」的核验依据。）

## 词表质量检查

### 1. 音节切分与读音一致性

上游给的是**连写拼音**（`zhongguo`），要转双拼必须先切成音节。转换时先做动态规划切分，再用每个汉字在 `pinyin-data` 里的实际读音做交叉约束，要求**汉字数与音节数相等、且每个音节都命中该字的读音**。

| 结果 | 数量 |
|---|---|
| 切分唯一且读音吻合 | 8190 |
| 切分有歧义（多解） | **0** |
| 无法通过约束 | 2 |

切分零歧义是很强的信号，说明词表的拼音列是逐字读音的忠实连写，可以放心自动化处理。

### 2. 被剔除的 2 个词

| 词 | 原因 |
|---|---|
| 阿Ｑ | 汉字列含全角字母 `Ｑ`，不是纯汉字 |
| 嗯 | 词表标 `eng`，但《现代汉语词典》记作 `ńg / ňg / ǹg`（pinyin-data 同），读音存疑；且它是单字词，本就在双字词子集之外 |

### 3. 一处数据瑕疵：üe 的两种写法

上游词表自身并不统一：

| 写法 | 例子 |
|---|---|
| `lve` / `nve` | `lvelve` 略略、`lveduo` 掠夺、`sinve` 肆虐 |
| `lue` / `nue` | `dalue` 大略、`yuelue` 约略、`baonue` 暴虐、`nuedai` 虐待 |

两种写法在双拼下**同码**（见 `03-自然码双拼.md`），因此转换脚本把 `lue/nue` 当作 `lve/nve` 的等价别名，不影响产物。

（对比：`lü` / `nü` 一律写 `v`，如 `lvse` 绿色、`nvzi` 女子。所以瑕疵仅限于 `üe`。）

### 4. 同音词

8173 个双字词里只有一对同音词：「**程度**」和「**成都**」，双拼码同为 `igdu`。影响 `log2(8173/8172) ≈ 0.0002 bit`，可忽略；对使用者反而是容错，记成哪个都能打出同一串密码。

## 已产出的词表

| 文件 | 词数 | 格式 | 生成脚本 |
|---|---|---|---|
| `wordlist-zh-cg.txt` | 8173 | 每行一个中文词 | `tools/make-wordlist-cryptogun.py` |
| `wordlist-shuangpin-cg.txt` | 8173 | `中文词<TAB>双拼码`（4 字母定长） | 同上 |

词数的来龙去脉：上游 8192 行 → 去 1 个重复词 → 8191；再剔除两类共 **18 个**词 → **8173 词**。

第一类（14 个）：编码本身不唯一。词典自身就记录了**音节不同**的多个读音，去掉声调后编码仍不唯一：

```
大夫 dafu|daifu      便宜 bianyi|pianyi     同行 tonghang|tongxing
琢磨 zhuomo|zuomo    调配 diaopei|tiaopei   下调 xiadiao|xiatiao
朝阳 chaoyang|zhaoyang  差事 chashi|chaishi  调拨 diaobo|tiaobo
明朝 mingchao|mingzhao  得了 dele|deliao     罢了 bale|baliao
本色 bense|benshai   温和 wenhe|wenhuo
```

加声调救不回来它们（声母韵母本身就不同），只能靠选定读音，故剔除。这属于「不能正常使用」，并非误删。

第二类（4 个）：书面语中两个读音都成立（人工复核后追加，逐条注明理由，见脚本中的 `MANUAL_DROP`）：

```
随行  suíxíng（随行人员）/ suíháng（随行就市）
朝日  zhāorì（早晨的太阳）/ cháorì
中的  zhòngdì（射中靶心）/ zhōngde
都会  dūhuì（大城市）/ dōu huì
```

> 另有两类不剔除：「泄露」（书面语只读 lù，lòu 是口语）、
> 「这些/那些」（zheixie/neixie 只是口语合音）。本词表按书面语制作。

### 一处已知的键位冲突：`lo` / `luo`

双拼里韵母 `uo` 落在 `o` 键，因此 `luo → lo`；而音节 `lo`（「咯」「啰」等语气词）本身也编码为 `lo`，两者同码。这是自然码键位的固有性质，加分隔符也解决不了。

实测影响：8173 词的词表里没有因此产生任何实际重码，因为 `lo` 音节的常用词极少。记录在此备查。

### 只在不同声调的词不受影响

如「摆设」bǎishè/bǎishe，双拼输出不带声调，这类词的码唯一，无需剔除。实测这类有 68 个，全部保留，见 `tools/diag-multi-reading.py`。

### 人工抽查要点

自动化只能核查结构，查不出是否难联想：

- 有没有生僻或想不起意思的词
- 有没有读音拿不准的词（自动化只查了与词表读音是否吻合，查不出你会怎么读）
- 碰到这类词，生成密码时换一组候选即可，不必改词表

## 词表设计的三条路线

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 前缀码 | 词表保证「无词是另一词的前缀」 | 无需分隔符 | 要排除部分高频词 |
| 分隔符 | 词间插 `.` 或 `-` | 最简单，保留全部词 | 多几个字符 |
| **定长码** | 双拼加全双音节词表 | 无需分隔符，无需排除词 | 要求词表全是双音节 |

本项目走第三条（双拼每字 2 字母，词表全双字词，于是每词 4 字母定长），这是唯一不需要做任何妥协的路线。

唯一可解码的真正目的，是保证「词序列 → 密码串」是**单射**。若多个词序列产出同一串，密码串的总数小于词序列总数，攻击者的搜索空间随之变小，有效熵下降。它并不是为了让人类能从密码反推词。
