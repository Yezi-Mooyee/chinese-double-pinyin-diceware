# 03 自然码双拼编码

## 状态：键位表**已核实**（2026-10 更新）

本文件早先标注「键位表尚未核实」，理由是：凭记忆写出的键位表一旦有误，产出的密码会自洽却错误。
按错误规则生成的密码照样能开库，直到某天按正确规则回忆时才打不开，而那时已经无法自查。
这个顾虑是对的，现在它已经被解决：

| 步骤 | 内容 | 产物 |
|---|---|---|
| 1. 方案本身 | 自然码（周志农，1980 年代）。[Rime](https://rime.im) 的 [`rime/rime-double-pinyin`](https://github.com/rime/rime-double-pinyin) 的 `double_pinyin.schema.yaml` 是它的实现之一，仅用于核对 | - |
| 2. 交叉验证① | [`iDvel/rime-ice`](https://github.com/iDvel/rime-ice) 的同一方案文件，键位表逐条一致（与 Rime 同源，算不得独立） | - |
| 3. 交叉验证② | [`fcitx/libime`](https://github.com/fcitx/libime) 的 `SPMap_C_Ziranma`/`SPMap_S_Ziranma` 键位表。**Fcitx5 的生产代码，与 Rime 完全独立**，逐项一致 | - |
| 4. 交叉验证③ | [dgod《自然双拼编码规则》](https://yong.dgod.net/read.php?tid=655&fid=3)（自述抄自自然码使用手册）、[博客园《自然码双拼》](https://www.cnblogs.com/cuishengli/p/3163322.html)、[Chinese SE #30381](https://chinese.stackexchange.com/questions/30381/how-to-type-zero-initial-in-the-common-shuangpin-pinyin-keyboard-layouts) 三处独立复述互证 | - |
| 5. 全量模拟 | 把规则跑一遍**全部 420 个普通话音节**，检查是否都是 2 字母、有无码冲突 | 脚本可随时重跑 |
| 6. 项目内校验 | 模拟结果 `zhong→vs`、`guo→go`，即「中国」= `vsgo`，**与本文档早先独立记录的写法完全吻合** | - |
| 7. 用户确认 | ü 用 `v`、u 用 `u`；`ju/qu/xu/yu` 中 ü 省点写作 `u`，两种打法都能出字 | 用户口述 |

Rime 的实现可以当作可靠参照，因为它是真正在跑的输入法定义，并非二手整理的对照表。
仓库 README 明确标注 `自然码双拼 | double_pinyin`，schema 内 `name: 自然码双拼`，同一仓库里另外五个文件分别是智能ABC、小鹤、微软、拼音加加、四通，没有拿错的可能。

键位映射是方案本身的事实，不受著作权保护（周志农已声明免费授权）。上面几项实现是对同一方案的各自表达，本项目只据此核对，没有复制其代码或文本。转换实现见 `tools/shuangpin.py`。

> **仍然建议实测**：本文档末尾给了 16 个验证样本字，用你的输入法打一遍，与下表逐项比对。

## 键位表

### 声母（23 个）

| 声母 | 键位 | 声母 | 键位 | 声母 | 键位 |
|---|---|---|---|---|---|
| b | `b` | g | `g` | zh | **`v`** |
| p | `p` | k | `k` | ch | **`i`** |
| m | `m` | h | `h` | sh | **`u`** |
| f | `f` | j | `j` | r | `r` |
| d | `d` | q | `q` | z | `z` |
| t | `t` | x | `x` | c | `c` |
| n | `n` | y | `y` | s | `s` |
| l | `l` | w | `w` | | |

声母一律打它本身的键，**只有 `zh / ch / sh` 三个例外**：`v / i / u`。
（记忆：`v`、`i`、`u` 是键盘上右手最顺的三个位置，自然码把它们给了最高的三个声母。）

### 韵母（35 个）

| 韵母 | 键位 | 韵母 | 键位 | 韵母 | 键位 |
|---|---|---|---|---|---|
| a | `a` | ia / ua | `w` | uo | `o` |
| o | `o` | ie | `x` | uai | `y` |
| e | `e` | iao | `c` | ui | `v` |
| i | `i` | iu | `q` | uan / üan | `r` |
| u | `u` | ian | `m` | un / ün | `p` |
| ü | `v` | in | `n` | uang / iang | `d` |
| ai | `l` | ing | `y` | ong / iong | `s` |
| ei | `z` | ang | `h` | üe | `t` |
| ao | `k` | eng | `g` | er | `r` |
| ou | `b` | en | `f` | | |
| an | `j` | | | | |

几个要点

1. `ü` 打 `v`，与「手写省略点」的规则同源：`lv`绿、`nv`女、`lve`略、`nve`虐。
2. `ju / qu / xu / yu` 就写 `u`，不用写 `v`。这几个音节里 `u` 本来就是 `ü` 的省点写法，标准编码是 `ju`。有些输入法额外接受 `jv`，但那只是额外可接受的输入，本词表统一输出省点形式。
3. `uo` 和 `o` 都落在 `o` 键：`guo`→`go`、`luo`→`lo`。
   ⚠️ 这会造成一处码冲突：音节 `lo`（「咯」等语气词）与 `luo` 同码。
在 8120 词的双字词表里，它只导致「略为」和「略微」这一对同音词撞码，影响 `log2(8120/8119) ≈ 0.0002 bit`，可忽略。
4. `v` 键身兼两职：既是声母 `zh`，又是韵母 `ui` / `ü`。
   所以 `zhui` → `vv`，`zhui` 的两个字母都是 `v`。这是正常的，不冲突。

### 零声母音节（a / o / e 开头，共 12 个）

这是各方案差异最大、最容易错的地方。自然码的规则是，**单字母韵母要双写**：

| 音节 | 码 | 音节 | 码 | 音节 | 码 |
|---|---|---|---|---|---|
| a | `aa` | e | `ee` | o | `oo` |
| ai | `ai` | ei | `ei` | ou | `ou` |
| ao | `ao` | en | `en` | **ang** | **`ah`** |
| an | `an` | **eng** | **`eg`** | er | `er` |

要点：

- 只有 `a` `o` `e` 这三个单字母韵母需要双写。其余照韵母键打，但因为前面没有声母，就用韵母本身的全拼形式凑满两键。
- `ang` → `ah`、`eng` → `eg` 是最反直觉的两个，务必实测确认。
- `y` / `w` 开头的音节按「y/w 是声母」处理，不需要双写：
  `yi`→`yi`、`wu`→`wu`、`ying`→`yy`、`weng`→`wg`、`yue`→`yt`。

## 定长码性质（本方案的核心优势）

双拼**每字恰好 2 个字母**，因此：

- 双音节词 = 恰好 **4 个字母**
- 词表若全为双音节词 ⇒ 每词定长 ⇒ **定长码**

| 问题 | 是否还存在 |
|---|---|
| 词边界歧义 | ❌ 不存在（按每 4 字母切分，唯一） |
| 需要分隔符 | ❌ 不需要 |
| 需要前缀码 | ❌ 不需要 |
| 密码空间塌陷 | ❌ 基本不发生（仅同音词，见上文第 3 点） |

已对 8120 词的双字词表做过检查：**4 字母码只有 1 组重复**（「略为」/「略微」，同音词），其余 8119 个码互不相同，映射是单射的。

若使用混音节词表（含单字词 2 字母、三字词 6 字母），长度变为 2/4/6 不等，会出现切分歧义，此时**必须加分隔符**（如 `.`）。本仓库只发布全双字词表。

## 输出形态对比

| | 全拼输出 | 双拼输出 |
|---|---|---|
| 例（「中国」） | `zhongguo` | `vsgo` |
| 7 词长度 | 约 43 字符 | **28 字符** |
| 对熟练用户的转换成本 | 有（需拼写知识） | **≈ 0**（技能内化的直达映射） |
| 熵 | 90.91 bit | 90.91 bit（相同） |

熵与输出形态无关，只取决于词表大小 × 词数。

> 不要以「双拼多一层转换」为由质疑本方案：对长期自然码用户，汉字到键位是**程序性记忆**，
> 不经过全拼这一层。

## 转换流程

```
汉语词序列（记忆载体）
    ↓ 逐字转自然码双拼（熟练用户的程序性技能）
双拼串（密码输出）
```

规则公开性：自然码是公开标准，键位表可查，可以打印，也可以抄下来，写下来不影响安全性。
所以不存在「规则遗忘」这类风险，忘了就查表。唯一需要真正记住的是词序列本身。

## 转换时的技术要点

1. 多音字以《现代汉语词典》规定读音为准；双拼不带声调，所以声调有争议不影响输出，真正要避开的是整词有两种读法、双拼码却不同的词。
2. 转换脚本可重复执行且确定性：`tools/make-wordlist-cryptogun.py` 对同一输入永远产出同一输出。
3. 词表的音节切分有依据，不是靠猜：先用动态规划切分，再用每个汉字在 `pinyin-data` 里的实际读音做交叉约束，要求汉字数与音节数相等且读音吻合。8192 个词中 8190 个通过，只有 2 个被剔除（见 `02-词表资源.md`）。
4. 定稿前请跑一遍上面的验证样本。
