## 一、结论

| 我们产出的文件 | 里面有什么 | 用到了谁的什么内容 | 可否再分发 |

## 二、逐项说明

### 1. 词表：用了 cryptogun 的「选词结果」

`wordlist-zh-cg.txt` 里的 8173 个词形本身是语言公共财产（谁都能写「中国」「工作」）。真正取自 cryptogun 的，是选出这 8192 个词的那个选择。

cryptogun 是 MIT，允许再分发与修改，只需保留版权与许可声明。它的版权声明原文见根目录 `THIRD-PARTY-NOTICES.md`。

还有一点能降低风险：cryptogun 仓库里有 `generate_wordlist.py`，说明它的词表是程序按规则从《现代汉语常用词表》筛出来的，属于机械筛选，独创性很低（汇编作品的保护要求选择或编排具有独创性）。

处置：保留，在 `THIRD-PARTY-NOTICES.md` 中注明。

### 2. 双拼码：是「计算结果」，不是复制的内容

`wordlist-shuangpin-cg.txt` 的第二列是把词按自然码键位算出来的 4 个字母，没有从任何文件里抄，是按公开标准计算出来的结果。

### 3. 读音：取自上游词表自带的拼音列

读音的唯一来源是 cryptogun 词表自带的拼音列（MIT）。它自身约 21 处标注错误在生成脚本里逐条列出并修正，每条附理由。

这里不需要引入任何第三方词典数据。读音本身属于普遍事实，按《著作权法》第五条第（二）项，单个读音是「单纯事实消息」，不构成受保护的表达。

### 4. 双拼键位：自然码方案本身的版权

已查证：自然码由周志农发明。他本人 2006 年的说明（[原文](https://blog.muyu.org/674)）：

> 虽然自然码双拼占有率不高，**但是版权是明确的，并且同意免费授权**，这样微软才采用了。

也就是说，键位方案的版权人是周志农，且已免费授权。

本项目用的是方案本身（声母、韵母到键位的映射）：

- 以数据表形式独立整理（`tools/shuangpin.py`），不含 Rime 或 libime 的代码或文本；
- 用 Rime 与 Fcitx5 libime 两个相互独立的实现交叉验证，证明这是标准而不是某家独创，核对结果为 422 个音节 0 处差异。

处置：保留，在文档中注明自然码及其作者周志农。本仓库不含上述实现的任何代码或文本。

### 5. 为什么不用覆盖率更高的词级读音数据

开发期间实测过两份词级读音数据，它们都会把正确的标注改错：

| 数据源 | 协议 | 实测问题 |
|---|---|---|
| CC-CEDICT | CC BY-SA 3.0 | 「大夫」取成 dà fū（士大夫义）、「便宜」取成 biànyí（便宜行事） |
| phrase-pinyin | MIT | 「古朴」「质朴」读成 gǔpiào / zhìpiào（取「朴」的姓音 piáo），凭空多出 3 组重码 |
| **cryptogun 自带拼音列** | **MIT** | 质量最好，自身约 21 处标注错误已逐条修正 |

所以最终以 cryptogun 自带的拼音列为准，只叠加一份逐条注明理由的手工清单。这样既拿到了 MIT 的干净许可，词表质量也不降级（重码仍为 1 组）。

这两份数据都不在仓库中。需要时可自行下载用于交叉核验，见 `tools/fetch-data.py`。

## 三、法律依据

- **GNU GPL 官方 FAQ**：「when a program translates its input into some other form, the **copyright status of the output inherits that of the input** it was generated from.」意思是输出继承输入的权利状态。输入全是 MIT ⇒ 输出是 MIT。
- **《中华人民共和国著作权法》第三条**：受保护的是「具有**独创性**的智力成果」。
- **第五条**：本法**不适用于**「（一）法律、法规，**国家机关的决议、决定、命令和其他具有立法、行政、司法性质的文件**……（二）**单纯事实消息**；（三）历法、**通用数表**、通用表格和公式」。
  - 《普通话异读词审音表》属第（一）项，不受著作权保护；
  - 单个汉字的读音属第（二）项「单纯事实消息」。
- **第十五条**：汇编作品的著作权「**对其内容的选择或者编排**体现独创性」才产生。受保护的是**选择与编排**，不是内容本身。这正对应「整理读音是脑力劳动」这一直觉：劳动受保护的部分是编排，不是读音事实。

《现代汉语词典》是商务印书馆的商业出版物，有版权。本项目没有复制它的任何文本，只把它的读音规范当作事实来遵循；逐条修正清单都注明了理由，可复核。

```bash
python tools/fetch-data.py
python tools/fetch-data.py --proxy 127.0.0.1:26561   # 连不上时走代理
python tools/fetch-data.py --list                    # 列出全部数据源
```

### 防「原作者删库」

数据靠下载意味着上游仓库一删，脚本就失效。三层防护：

1. **固定 commit**：把 `tools/fetch-data.py` 里的 `@master` 换成具体 commit hash，行为就固定了。
2. **fork 一份到自己的账号**（推荐）：在 GitHub 上对 `cryptogun/diceware` 和 `mozillazg/pinyin-data` 各点一次 Fork，再把 `fetch-data.py` 里的 `owner/repo` 换成分叉。
3. **固化校验值**：`fetch-data.py` 每次下载都打印 `sha256:` 前 16 位，首次下载后把这些值写死成期望值，之后不符就报错。

> jsDelivr CDN 与 GitHub 仓库同生共死，上游删库 CDN 也会 404。CDN 只解决 raw.githubusercontent.com 连不上，防删库只能靠 fork。
