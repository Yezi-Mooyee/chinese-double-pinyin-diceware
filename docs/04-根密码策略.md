# 04 根密码策略

## 目标

一个只靠记忆即可复现、且熵足够的根密码，用于保护密码管理器数据库。

## 熵要求与词数

按每词 12.997 bit 计算：

| 词数 | 熵 | 评价 |
|---|---|---|
| 5 | 65.0 bit | 偏低，不建议 |
| 6 | 78.0 bit | 可用下限 |
| **7** | **91.0 bit** | **推荐** |
| 8 | 104.0 bit | 更保险，但多一个记忆单元 |

**80 bit 以上即足够**，因此 7 词是自然选择。

强度只取决于词数与词表大小，与输出长度无关。全拼输出 43 字符与双拼输出 28 字符，强度完全相同。

## 记忆机制

- 记忆载体是中文词：大脑擅长记词，不擅长记随机串
- 输出靠双拼技能：程序性记忆，直达映射，不经过全拼
- 二者分离，于是记住的是词，打出的是键位

辅助手段：

- 把词序列编成具体、具象、反常的场景（`cryptogun/diceware` 的 README 里有二十余组示例）
- 挑几组容易编出画面的，编不出来的重新生成

## 保管策略

**纯记忆，不写纸。**

纸质保管的问题在于防不住能接触住所的人，而且需要额外建立一套物品管理体系。这些顾虑已经论证过，不必再劝。

接受的风险是：遗忘等于数据永久无法恢复，除非另有备份途径。

## 降低遗忘风险

1. **初期高频输入以固化记忆**：新设备建立数据库后的头一两周，刻意每天用根密码解锁几次，暂不启用快速解锁，确认牢固后再启用。
2. **定期自检**：
   - 默背词序列
   - 完整走通从词到双拼的链路，确认自己真能打出正确的串，而不只是把词回忆出来
   - 参考：`cryptogun/diceware` 的作者建议设置每月提醒闹钟默背
3. **写下来的规则不能用来判断对错**：自然码是公开标准，规则本身可查，所以自检的重点永远是词序列。

## 可选的后路

若某次自检失败，再考虑启用：

- 一张只作保险、日常不触碰的纸，放在不易遗忘的锚点处
- 异地保管，或交给信任的人

这些都是已被评估并暂不采用的选项，不必主动推动。

## 两个库需要两个不同的根密码

密码键盘与 KeePassXC 各需一个根密码，**必须不同**，一个泄露不应牵连另一个。

## 已排除的保管与生成方式

见 `00-原始项目说明.md` 的「排除的方案」表。要点重述：

- 写纸上（防不住接触住所的人）
- 提示纸（提示无法把随机密码的候选缩到一个，对完全遗忘无效）
- 延长闲置锁定时长（解锁状态下浏览器集成等全部可用，延长等于长期敞开门）
- 依赖 Windows Hello PIN 作为主要解锁（共享凭据，作用域覆盖整个系统）
