# 06 如何生成根密码

本文是操作手册：从词表走到一串能背下来的根密码。

> 读音标准与数据源的版本记录见 `07-读音标准与数据来源.md`。

---

## 一句话流程

```
从双拼词表随机选 7 个词  →  编成一个具体、反常的画面记住它
                        →  用自然码双拼把 7 个词打出来
                        →  得到 28 个字母的根密码
```

你记的是中文词，打出来的是双拼。两者分离，这是本方案的立足点。

---

## 一、用哪份词表

| 文件 | 词数 | 码 | 用途 |
|---|---|---|---|
| `wordlist-shuangpin-cg.txt` | 8173 | 4 字母定长 | ⭐ **主用：生成密码** |
| `wordlist-zh-cg.txt` | 8173 | - | 纯中文词表，每行一个词 |

两份内容相同，一份带双拼码、一份不带。

### 为什么是 cryptogun 版

| 指标 | cfbao 版（未采用） | **cryptogun 版** |
|---|---|---|
| 26 个常用探针词命中 | **0 / 26** | **22 / 26** |
| 词性构成 | 8121 双字 + 14 单字 + 57 三字 | **8192 全双字** |

cfbao 的拼音要构成前缀码以保证拼接无歧义，代价是砍掉大量常用词：「中」在表中 ⇒ 所有 `zhong…`（中国、中文、中心）全被排除。本方案用双拼定长码，本来就自带唯一可解码性质，不需要前缀码，这个约束对我们是纯损失。

8173 个词全是双字词，不含单字。现代汉语里单字不是独立的记忆单位。

## 二、不加声调

先看数据（`tools/entropy.py` 实测，7 词）：

| 方案 | 词表 | 每词熵 | 7 词熵（真实） | 重码 | 输出长度 |
|---|---|---|---|---|---|
| **不加声调** | 8173 | 12.997 bit | **90.975 bit** | 1 组同音词 | **28 字符** |
| 加声调 | - | - | 约 +0.002 bit | 0 组 | 约 41 字符 |

真实熵由 `tools/entropy.py` 计算，已扣除重码碰撞损失；公式经小规模精确枚举验证一致，见 `tools/audit.py`。理论上限 `7·log₂8173 = 90.977`。**每次改动词表都必须重算。**

声调**不增加熵**。它是词读音的一部分，由词唯一确定，不带来新的随机性。唯一的熵收益是消除同音词撞码，实测约 **+0.002 bit**，代价是输出从 28 字符涨到约 41 字符。

更要紧的是规则问题。加声调必须引入一条条件规则：

> 多音词不加声调

这条规则有三个问题：

1. **判据不完全公开**：完整判据是《现代汉语词典》第 7 版，无机读版；国家级的《普通话异读词审音表》（1985）只覆盖异读词（约 800 条）。
2. **每次输入都要现场判断**：得当场想这个词是不是多音词，规则进入了输入动作里。
3. **换来的熵只有 +0.002 bit。**

这违反了本方案的底线：**规则必须公开、明确，且不成为记忆负担**。

不加声调时，规则就是「汉字 → 双拼」，零条件分支，输出也不带声调，于是任何异读都不影响结果。

> 带声调版曾实现过，2026-10 移除。除了上述理由，它还依赖额外的词级读音数据，而那些数据要么许可有传染性，要么实测读音不准。

## 三、用附带脚本生成候选（推荐）

```bash
python tools/pick-passphrase.py                    # 3 组候选，每组 7 词
python tools/pick-passphrase.py -n 8               # 每组 8 词
python tools/pick-passphrase.py -p 4096            # 只用最常用的 4096 个词
python tools/pick-passphrase.py -g 5               # 打印 5 组
python tools/pick-passphrase.py --show-codes       # 同时显示每词的双拼码
```

输出形如：

```
词表        : wordlist-shuangpin-cg.txt  (共 8173 词)
实际词池    : 8173 词，每词 12.9967 bit
每组        : 7 词 = 90.977 bit
输出长度    : 28 个小写字母
随机源      : Python secrets (操作系统 CSPRNG)，不放回抽样

【候选 1】
  词  : 期望 不枉 起步 眨眼 一侧 热身 刷卡
  码  : qiwh buwh qibu vayj yice reuf uwka
  密码: qiwhbuwhqibuvayjyicereufuwka
```

随机源用 Python `secrets`（操作系统 CSPRNG），选词走 `randbelow`，均匀、无取模偏置。

多生成几组，挑一组能编出画面的（见第五节），其余当场丢弃。

### 安全提醒

- 不要把候选密码粘进任何聊天窗口、云笔记、剪贴板同步工具。
- 用完关掉终端窗口，别让它留在回滚缓冲里。
- 脚本只往屏幕输出，**不写任何文件**。

## 四、要物理随机就用硬币

不信任计算机随机数的话，用硬币。8173 不是 6 的幂，二进制最干净：

1. 掷 **13 枚硬币**（或同一枚掷 13 次），按顺序记正/反 = 1/0，得到一个 0 到 8191 的数。
2. 结果 **< 8173**：取 `wordlist-shuangpin-cg.txt` 的**第（结果 + 1）行**。
3. 结果 **≥ 8173**：**作废重掷**（这步不能省，否则分布不均匀）。

重复 7 次。

> 别用所谓「随机数生成网站」或手机骰子 App。那等于把随机性外包给一个你看不见的程序，而你本来就是为了不信任程序才用硬币的。

## 五、定稿：怎么从候选里挑一组

对每一组 7 个词，问自己：

1. 画面要具体，标准是能在脑子里看见。含糊地觉得大概能记住不算。
   最好荒谬、有动作、有颜色，大脑对反常的东西记得牢。
2. 检查有没有读不准的词。双拼不带声调，所以多音字基本不影响
   （只有整词有两种读法且声母韵母不同时才会出问题，这种词极少）。
   真碰到就换一组。
3. 合上屏幕，看能不能默背出词序列。背不出就换组，别硬撑。

选定后，其余候选立即丢弃。留着当备用等于把熵摊薄到几组上。

## 六、从词到密码

用你的双拼技能：

```
期望 → qi + wh → qiwh
不枉 → bu + wh → buwh
...
```

每词 4 字母，直接连写：

```
qiwhbuwhqibuvayjyicereufuwka     ← 28 字母，这就是根密码
```

键位表见 `03-自然码双拼.md`。规则是公开标准，写下来不影响安全，唯一需要真正记住的是那 7 个词。

## 七、常见问题

**Q：有没有真正撞码的词？**
有 1 组同音词（「程度」和「成都」都是 `igdu`），同音必然同码。影响 `log2(8173/8172) ≈ 0.0002 bit`，可忽略；反过来还是好处：记成哪个都能打出同一串。

**Q：多音字会不会坑我？**
不会，词表已经处理干净了。多音词分两类：

- 各读音只有声调不同（如「摆设」bǎishè/bǎishe）：双拼不带声调，码唯一，**零风险**。这类 68 个，全部保留。
- 各读音声母韵母也不同（如「大夫」`dafu`/`dlfu`、「便宜」`pianyi`/`bianyi`）：码本身就不唯一，加声调也没用。这类 18 个，已整词剔除。

所以词表里每一个词的编码都是确定的。

**Q：ü 怎么打？**
ü → `v`，u → `u`。`ju / qu / xu / yu` 这类（j q x y 后面本来是 ü）标准写法就省点作 `u`，所以打 `ju`，不用打 `jv`。

**Q：要不要输声调？**
默认不要。理由见第二节。

**Q：这个密码够强吗？**
7 词 = 90.98 bit。`04-根密码策略.md` 已确认 80 bit 以上足够。

**Q：两个库呢？**
KeePassXC 和密码键盘各要一个根密码，**必须不同**。跑两轮上面的流程。

## 八、复现与审计

所有产物都由 `tools/` 下的脚本确定性生成，可随时重跑核对：

| 脚本 | 作用 |
|---|---|
| `tools/make-wordlist-cryptogun.py` | ⭐ 生成词表（中文词表 + 双拼词表） |

| `tools/diag-rare.py` | 生僻度检查（需先跑 `fetch-data.py`） |
| `tools/compare-en.py` | 与英语 diceware 词表对比熵与长度 |
| `tools/fetch-data.py` | 下载可选的外部核验数据 |
